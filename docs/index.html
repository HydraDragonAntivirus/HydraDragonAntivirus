OpenMalwareScannerPortable

Multi-engine static malware scanner in a single DLL: ClamAV signatures, YARA-X rules, Unicorn CPU-emulation unpacker, ML ensembles, Hayabusa event rules and Authenticode + catalog verification — behind a plain C FFI. Plus a Web/WASM edition that runs fully client-side.

Engines

ClamAV signatures

Rust ClamAV engine with bytecode VM, daily databases and archive recursion. ~70MB DB.

YARA-X rules

Compiled Valhalla threat-intel ruleset, scanned over raw, unpacked and overlay bytes (0.95 per hit).

Unicorn unpacker

x86/x64 CPU emulation dumps packed payloads back into the scan pipeline (ClamAV + YARA + ML rescan).

ML ensembles

Gradient-boosted tree models for PE (≥0.71), JavaScript (≥0.75) and URL/phishing (≥0.50).

Hayabusa / Sigma

Windows EVTX forensics and live system-event log scanning.

Authenticode + catalog

WinVerifyTrust plus CatRoot catalog fallback: catalog-signed OS binaries (conhost, notepad, …) verify as trusted with the catalog signer name. Works for every file type, extension or not.

Heuristics

Null-padding strip, PE overlay binder check (validated MZ→PE only — installer shapes like 7z SFX don't trip it), decompression-bomb guard, SHA-1 collision attack detection.

System checks

PUA autostart registry rules and hosts-file hijack detect & restore.

C FFI API

FunctionWhat it does
openedr_static_initLoad rules/models from a directory (NULL = next to the DLL).
openedr_static_scan_fileFull multi-engine scan of a file path → JSON.
openedr_static_scan_bytesScan an in-memory buffer → JSON.
openedr_static_scan_urlURL / phishing score → JSON.
openedr_static_scan_evtxScan an .evtx file with Hayabusa rules.
openedr_static_scan_system_eventsScan live Windows event logs.
openedr_static_check_registryCheck a Run/persistence key against PUA rules.
openedr_static_check_hosts_fileDetect hosts-file hijacking (NULL = default).
openedr_static_restore_hosts_fileRestore the clean hosts template (optional backup).
openedr_static_free_stringFree every heap string the API returns.
Note: no cloud, no SHA-1 identity (SHA-256 only). The retired Comodo FLS client was removed; verdicts come only from local engines.

Verdicts

VerdictMeaning
MaliciousScore ≥ 0.85 — signature hit or high-confidence stack.
SuspiciousScore ≥ 0.50, or heuristic-only evidence.
CleanSHA-256 whitelist hit, or trusted signature with no other signal.
UnknownNo engine fired. Unsigned + unknown = unknown, never malicious by default.

Report JSON carries target, file_size, sha256, verdict, max_threat_score (0.0–1.0), detections[{layer, name, score, details}], signer_info{is_signed, is_trusted, signer_name, status, is_catalog_signed}.

Web / WASM edition

OpenEDR/openedr_web compiles the static core to wasm32-unknown-unknown and runs 100% client-side: same tree models and YARA-X engine, registry rules rewritten as in-PE string rules, same thresholds and verdict gating. What's out by design: ClamAV database, native Unicorn, WinTrust, Hayabusa, archive extraction.

capstone.js assist

Optional drop-in disassembles PE sections in-page and feeds instruction counts back into the scan.

unicorn.js assist

Optional drop-in emulates the entry point, diffs memory and re-scans dumped regions as Unpacked: findings.

False positives

Signed binaries fast-path to Clean; 256k known-good SHA-256 hashes are whitelisted; overlay findings require a validated embedded PE; installer shapes (7z SFX, Inno, NSIS) don't trip heuristics alone. Python-source and Java malware are a known blind spot (PE/JS/URL models only).
