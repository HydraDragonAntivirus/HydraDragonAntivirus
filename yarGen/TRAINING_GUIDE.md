# HydraDragonSig & yarGen-Sig Training Guide

This guide details how to train **HydraDragonSig** threat signatures against all supported datasets: Windows PE binaries, JavaScript files, and Android APK packages. It also covers how to update benign databases and verify generated rules with zero false-positive tolerance.

---

## 📌 1. Dataset Architecture & Directories

| Platform / Format | Benign Dataset | Benign DB Files (`yarGen/dbs/`) | Target Malware Dataset |
| :--- | :--- | :--- | :--- |
| **PE (Windows)** | `...\usbdosyalar\data2` (200,000+ files) | `good-strings-part*.db`<br>`good-opcodes-part*.db`<br>`good-strings-benign_data2.db` | `...\usbdosyalar\datamalicious`<br>`...\datamalicioussmall` |
| **JavaScript** | `...\usbdosyalar\javascript\data2` (53,000+ files) | `good-strings-benign_javascript_data2.db`<br>`good-opcodes-benign_javascript_data2.db` | `...\usbdosyalar\javascript\malicious` |
| **APK (Android)** | `...\HydraDragonAV-Mobile\dataset\benign` | `good-strings-benign_apk.db`<br>`good-opcodes-benign_apk.db` | `...\HydraDragonAV-Mobile\dataset\malicious` |

## 🛠️ 2. Creating & Updating Benign Databases (Benign DBs)

If you have a new benign software corpus and want to create or update baseline string/opcode databases:

```powershell
python yarGen/yargen_sig.py -c -i new_benign_set --opcodes -g "C:\path\to\clean_software"
```

This generates:
- `yarGen/dbs/good-strings-new_benign_set.db`
- `yarGen/dbs/good-opcodes-new_benign_set.db`

> **Note:** The workspace already includes pre-built databases containing over **34.6 million benign opcodes** and **77.3 million benign strings**. During signature generation, these databases load automatically to veto benign patterns.

## 🚀 3. Training & Generating HydraDragonSig Rules

Signature synthesis is executed through **`yarGen/yargen_sig.py`**. The original `yarGen.py` remains untouched.

### 3.1. PE Malware Training (Pilot / Small Dataset)
For rapid verification on small malicious corpora (`datamalicioussmall`):

```powershell
python yarGen/yargen_sig.py `
  -m "C:\Users\semae\OneDrive\Belgeler\usbdosyalar\datamalicioussmall" `
  --sig-yaml "OpenMalwareScannerPortable\hydradragonsig_rules\malware_pilot_rules.yaml" `
  --excludegood `
  --meaningful-words-only `
  -o "OpenMalwareScannerPortable\hydradragonsig_rules\malware_pilot_rules.yaml"
```

### 3.2. Full PE Malware Training (Production / Large Corpus)
For training on large enterprise PE malware collections (`datamalicious`):

```powershell
python yarGen/yargen_sig.py `
  -m "C:\Users\semae\OneDrive\Belgeler\usbdosyalar\datamalicious" `
  --sig-yaml "OpenMalwareScannerPortable\hydradragonsig_rules\pe_threat_signatures.yaml" `
  --excludegood `
  --meaningful-words-only `
  -fs 50 `
  -o "OpenMalwareScannerPortable\hydradragonsig_rules\pe_threat_signatures.yaml"
```
*(`-fs 50` skips files larger than 50 MB to prevent high memory usage).*

## 🔍 4. Anatomy of Generated Rules

Every signature generated by `yargen_sig.py` implements the following HydraDragonSig features:

1. **Stem-Based Grouping & Strain Merging:**
   - No arbitrary regex family carving. File basenames are preserved while stripping counter suffixes (`_53`, `_417_1`).
   - Identical strains merge into a single rule.
   - All sample filenames are recorded in `description` (`Samples: file1.vir, file2.vir`).
2. **Exclude Bytes (`excludes: [...]`):**
   - Populated with common compiler and runtime prologue sequences extracted from `good-opcodes*.db`. If any benign blob is present in the scanned file, the match is vetoed immediately.
3. **PE Icon Perceptual Fingerprints (`pe_icon_any`):**
   - Automatically decodes `RT_ICON` DIB/PNG resources from PE files.
   - Generates 64-bit difference hash (`dhash`) and 64-bit DCT perceptual hash (`phash`) with Hamming distance tolerances.
4. **Suspicious PE Imports (`import_any`):**
   - Matches distinctive execution and injection APIs (`VirtualAlloc`, `WriteProcessMemory`, `CreateRemoteThread`, etc.).
5. **High Section Entropy (`section_entropy`):**
   - Detects packed or encrypted sections (`min: 7.2`).
6. **APK ML & Permission Metrics (`feature_gte`):**
   - Incorporates dangerous permission thresholds (`dangerous_perm_count >= 3.0`) and DEX counts.

## 🧪 5. Rule Verification & Zero False-Positive Testing

To test and benchmark the compiled rules against real workloads:

### A. True Positive Detection Test (Malware Corpus)
```powershell
cargo run --manifest-path hydradragonsig/Cargo.toml -- `
  -r "OpenMalwareScannerPortable\hydradragonsig_rules\malware_pilot_rules.yaml" `
  "C:\Users\semae\OneDrive\Belgeler\usbdosyalar\datamalicioussmall" `
  -R
```

### B. Zero False-Positive Verification (Benign Corpus)
```powershell
cargo run --manifest-path hydradragonsig/Cargo.toml -- `
  -r "OpenMalwareScannerPortable\hydradragonsig_rules\malware_pilot_rules.yaml" `
  "C:\Users\semae\OneDrive\Belgeler\usbdosyalar\data2" `
  -R
```

> **Expected Result:** Due to the combination of string vetoes and exclude bytes, scanning the clean corpus should produce **0 findings**.

## ⚙️ 6. Performance & Memory Recommendations

- **RAM Requirements:** Loading 34.6M opcodes and 77.3M strings requires approximately **6 GB to 10 GB of system RAM**. Ensure sufficient memory is available before training large sets.
- **`--excludegood`:** Always include this flag so benign databases filter out false positives.
- **`--meaningful-words-only`:** Ensures only meaningful English words are retained for clean, readable rules.
