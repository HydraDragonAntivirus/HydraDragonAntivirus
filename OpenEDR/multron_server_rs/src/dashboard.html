Engine & limits

Unpacks every .xz kept file (stored compressed when disk space was low) next to itself and deletes the .xz only after the unpacked SHA-256 matches its name, so nothing is lost. Stops before free space drops under the low-disk threshold; files that fail stay as they are. Training and the type sort read the plain files.
Moves each kept file into a folder named after its file type: the HydraDragonSig type first (javascript, powershell, batch, vbs, python, pe32/pe64, elf64, apk, jar, dex, pdf, zip, ...), then the ClamAV type (hydradragonclamav .ftm magic: rar, html, text_ascii, ...) where HydraDragonSig only says text or archive. The content decides, never the file name; .xz files are unpacked to check. Files of unknown type stay in the category folder. New files are sorted this way when they are kept.
Moves the copies the server wrote into the ML dataset folders (<SHA256>.exe etc.) whose file is in multron_incoming/ to a backup folder next to the dataset folder (deleted_from_data2_pe, ...). Nothing is deleted; training never reads the backup folders. multron_incoming keeps the file with its telemetry; your own and public dataset files are never touched. Logged in dataset_moves.jsonl.

Move kept files to another disk

Copies kept files to a folder on the main PC (network share) or an external drive, checks each copy against its SHA-256 and then deletes it here. Moved files are no longer rescanned from this server.

Duplicate samples

The same SHA-256 kept more than once (under another file name, in two category folders, or plain and .xz). Keeps the copy in the folder of its current verdict (human verdict first), otherwise the uncompressed one, then the newest, and deletes the others. Also runs at every start; new duplicates are no longer stored.

Backup archive

Copies the whole database (telemetry with IPs and paths, human verdicts, signatures, TLSH, reports, bans, API keys, event log) and every kept file to the archive PC whenever its folder is reachable: every 5 minutes, only what changed. Nothing is deleted there, so files moved or removed here stay in the archive. Run the server on the archive PC from that folder with --archive: read-only, it serves file pages, the API and samples and picks up new data every minute. A sample whose verdict changed here is moved to its new category in the archive as well, and leftover duplicates are removed. Tip: set the move target above to <archive folder>\multron_incoming so moved files stay downloadable from the archive.

False-positive signature lists

Signatures turned off because they flag clean files, each with its reason. All three engines (ClamAV, HydraDragonSig, YARA) use .ign2 ignore lists in their rule folders, active after the next engine reload. For YARA, remove_excluded_rules.py -x <list>.ign2 also removes the rules from the sources for good before the next .yrc build. Add entries from a file's right-click menu or from human analysis.

Retrohunt

Every saved signature is matched against all kept files (every category of the work folder), like VirusTotal Retrohunt. Each match is rescanned with the full engine and the current settings, so its verdict updates; a human verdict still wins. Saving a rule again starts a new hunt.

Imphash signatures

The import hash of a PE you know is malicious flags every other PE with the same import table (only unknown / possible clean / suspicious results are raised; a human clean verdict always wins). Refused for .NET programs, import tables smaller than 10 entries and any imphash a clean file has (benign reference corpus or a human clean verdict). Applies to new scans at once. Open the file in VirusKovAlyzer and press Imphash signature, or give the SHA-256 of a kept file.

Company (signer) lists

One Authenticode signer name per line, exactly as in the certificate. Allow makes validly signed files clean (a broken or untrusted signature is ignored). Block marks the signer's files malicious. Analyst ClamAV and HydraDragonSig hits still apply on top; a human hash verdict always wins.
